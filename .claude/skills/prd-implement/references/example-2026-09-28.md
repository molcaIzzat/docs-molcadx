# Worked example — 2026-09-28 (four prd-syncs, PRD-003 + PRD-004)

Read this when sorting a delta into buckets, especially for the **Carry** bucket: it shows how one field's
meaning change in FOUNDATION rippled into two Production repos.

## The delta

Four prd-syncs landed the same morning (`6d9a679`, `961b6f2`, `cd04dc0`, `2106622`). The CHANGELOG
entries named the stories; the key decisions were:

- `OPERATION.uom_id` is now the **item unit** a cycle time is per ("20 seconds / pack"), not a time unit.
- `PRODUCT_CYCLE` (per-product reference cycle times, `US-FND-PRO-004`) **retired**.
- One `PRODUCT_UOM_CONVERSION` row covers both directions (forward ×, backward ÷; forward wins).
- Sidebar grouped by domain; BOM and Routing become separate pages; no "Work Master" or "Master data" label.
- Quality never converts units — mixed units refused at binding.
- `ASSET_STATE_LOG` ownership → PRODUCTION (spec still draft; no status change).

## Traps hit

- The conversion seed was stored backwards (`pack → carton × 12` means 1 pack = 12 carton). The PRD example
  says 1 carton = 12 pack: `from carton, to pack, 12`. Check seeds against the worked examples.
- Mixed `valid_to` conventions: work master treats `valid_to` as inclusive, F-06 conversions as exclusive
  (`valid_to > date`). Follow each spec; don't unify silently.
- A shared resolver was needed in four places (master-data API + web, Planning API, Performance API) —
  one source, copies with a "keep in step" header.
- The dev server's first load renders blank for a few seconds; plain `curl` output is reformatted by the
  rtk hook — use `rtk proxy curl`.
