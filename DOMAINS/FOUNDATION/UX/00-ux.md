# 00 — UX Map (FOUNDATION)

> Working draft (`foundation-domain`). Index: [`../AGENTS.md`](../AGENTS.md) §2.
> Behavioral counterpart: [`FLOW/00-flow.md`](../FLOW/00-flow.md).

**In short:** this folder declares **what the implementor sees and touches** for every
FOUNDATION module — one UX doc per module, numbered exactly like `DOCS-EN/` (`F-01` ↔
`01-`), plus one journey doc for the cross-module implementor setup. PRDs cite these
declarations via `SCR-*` anchors instead of describing screens inline.

> Scope note 2026-08-26 (PO): interaction declarations live **in each domain**, not in a
> separate design domain. PRODUCTION's own `UX/` series is deferred. Visual design, design
> system, and Figma handoff remain with a future `design-domain` (still unplanned in
> [02-domains](../../../DOCS/02-domains.md)).

## Layer stack

```
F-xx §9 (entities)            DOCS-EN module specs
   ↓
FLOW-xx (behavior)            FLOW/                      ← constraint tier
   ↓
UX-FND-xx (module screens)    UX/ (this folder)          ← decision tier
   ↓
UX-JRN-xx (journeys)          UX/ — compose cited screens only
   ↓
US-* (stories & metrics)      PRD cites the anchors above
```

Three-tier rule (constraint → implication → decision):
[FLOW-00](../FLOW/00-flow.md). A UX doc that restates a behavior rule is a defect; a flow
doc that prescribes a screen is out of scope.

## The 7-state matrix — every screen, every time

| State         | Meaning                                          | Requirement source                                     |
| ------------- | ------------------------------------------------ | ------------------------------------------------------ |
| Default       | normal populated use                             | —                                                      |
| Empty         | no data yet — "belum ada data", never a fake row | [P-02 §1.4](../../PRODUCTION/DOCS/03-performance.md)   |
| Loading       | skeleton; old values never shown as fresh        | PRD-001 §6                                             |
| Error         | last good state kept + what failed + retry       | PRD-001 §6                                             |
| Offline       | offline marker + age of local data               | [P-01 §5](../../PRODUCTION/DOCS/02-monitoring.md), KR 1B.2 |
| Success       | confirmation ≤1 s for operator actions           | PRD-001 §6                                             |
| No-permission | what's out of scope + who to contact             | PRD-001 §6                                             |

A screen may mark a state **N/A with a reason** (e.g. a read-only catalog has no offline
entry path) — silence is not allowed.

## Cross-cutting conventions

- **Delete requires confirmation.** Any action that destroys data the implementor can't
  trivially recreate (removing a declared row, not deactivating a master-data node — that's
  already covered by "deactivation, not deletion" in
  [00-foundation.md §3](../DOCS-EN/00-foundation.md)) shows a confirmation dialog naming
  what will be lost before it executes. Applies uniformly — a screen does not get to skip
  it because the action feels minor.

- **No "Work Master" menu item (PO, 2026-09-28 addendum, [2026-09-28 decision](../../../LOGS/decisions/2026-09-28-work-master-per-domain-operation-uom.md)).** "Work Master" stays the
  spec/module name (ISA-95 term), not a menu label. BOM and Routing are separate tabs on the
  Product detail page (2026-09-30), not a "Work Master" item.
- **Placement rule.** A new config that varies per domain goes into the domain groups, listed
  by **what the page is** (PM checklist, KPI), not grouped under a module label. **Data that
  belongs to one shared master record** (a product's BOM and Routing) goes on that record's detail
  page as a tab, even when only one domain reads it today; a license gate hides the tab (2026-09-30). A
  config shared by all domains goes into the shared items at the top (no heading). Shared masters are never inside a
  domain group.
- **Domain not licensed → one locked group heading.** The group shows collapsed, with a lock
  icon, and cannot be expanded; its items (PM checklist, KPI, anything later) are hidden. Tabs the domain
  gates on shared screens (BOM and Routing on Product detail, for Production) are hidden too.
  Clicking the heading opens the upsell / "contact your administrator" surface of
  [PLATFORM FLOW-01](../../PLATFORM/FLOW/01-module-entitlement-check.md). The "locked group
  heading" state is defined in [PLT-01 core concept 3a](../../PLATFORM/DOCS-EN/01-license-manager.md#core-concepts)
  and that FLOW (`platform-domain`); this doc cites them and does not redefine them.
- **Licensed domain, every item hidden** (tenant licensed for the domain but not for any of its
  modules): open — [PLATFORM FLOW-01 FL-3](../../PLATFORM/FLOW/01-module-entitlement-check.md#whats-still-unknown). Not decided here.
- A licensed domain whose item has no content yet still shows it and opens to that screen's
  empty state (e.g. `kpi-002.empty.domain`).
- **Runtime logs are not setup screens.** A runtime log (e.g. the operational-state log, `ASSET_STATE_LOG`) lives in its owning domain's app, not in this sidebar ([decision 2026-09-28](../../../LOGS/decisions/2026-09-28-asset-status-ownership.md)).
- The shared items at the top are never license-locked (FOUNDATION is bundled). Screens inside it
  keep any gate their own UX doc declares.

## Coverage rules (checkable)

- **D-1** Every §9 entity of the module appears in ≥1 screen of its UX doc.
- **D-2** Every screen cites ≥1 `US-*` story; where none exists, it cites the **KR 2.1
  blanket mandate** and is flagged `story TBD — PRD-002 candidate`.
- **D-3** A journey doc composes cited `SCR-*` only; it never specifies a screen it
  didn't cite.
- **D-4** PRD Expectation blocks cite `SCR-*` anchors; a screen's layout and state list
  declared here are not restated in a PRD ([03-prd-standard §3.5](../../../DOCS/03-prd-standard.md)).
  **Screen text is the exception:** the PRD copies it word for word from this folder (rule T-2).
- **D-5** Every declared screen that is being built has a **Screen text** block in its module
  UX doc (see "Screen text" below).

## Screen text — this folder is the source (PO decision, 2026-09-25)

Two builds of the same screen wrote different wording wherever the PRD left text open or gave
none. From now on every piece of text a user reads on a declared screen lives **here**, in the
module's UX doc, under a `## Screen text` section with one block per screen:

```
### SCR-FND-XXX-001 — <screen name>          (format example only, not real text)
| Key | Where / state | Text | Stories |
|---|---|---|---|
| `xxx-001.title` | Page title | "<exact title>" | US-FND-XXX-001 |
| `xxx-001.empty` | Empty state | TBD — PO | US-FND-XXX-001 |
| `xxx-001.error.duplicate-code` | Save, code already used | "Code <code> is already used." | US-FND-XXX-001 |
```

- **T-1 Exact wording, one home.** Titles, labels, buttons, state messages (the 7-state matrix
  above), validation errors and confirmations. **Key** is stable (`<module>-<nnn>.<element>`) so code
  can use it as the text ID. Values the screen fills in are written `<in angle brackets>`.
  **UI language (PO, 2026-10-02, prd-molcadx#24 item 22):** the UI ships in **English by default**, with
  an `en` / `id` language switcher. The Text column here is the English (`en`) text. Terms in both
  languages must match [01-glossary](../../../DOCS/01-glossary.md) and ISO 22400 (KR 2.2). This replaces
  "the entire UI is in Indonesian". Where the Indonesian (`id`) text lives is UX-0-1.
- **T-2 The PRD copies, the UX doc wins.** PRD Expectation tables quote the text word for word and
  name the key. If they differ, this folder is right; `prd-sync` corrects the PRD.
- **T-3 Undecided text is a row, not a gap.** Write the row with `TBD — PO` as its text. A build
  shows the placeholder `[TBD copy: <key>]` on screen — never its own wording.
- **T-3a Drafts.** A proposed wording waiting for PO review is written `"<text>" (draft)`. Builds may use
  it; it can still change. The PO removes `(draft)` when the wording is accepted.
- **T-4 Nothing on screen that isn't here.** A rule for developers (e.g. F-02 "no production-shift
  flag") is not screen text; don't turn it into a sentence on the screen unless a row says so.

**Copy style (for drafts and final text):** plain words, sentence case, short. No system words on
screen (no "IDP", "scope claim", "entity", field names). Buttons are a verb (+ noun): "Add unit", "Save",
"Deactivate". Page title = its sidebar label. Empty = "No \<things\> yet." + one line on why it matters.
Save error = "Couldn't save. Your changes are still here — try again." Offline (master data) = "You're
offline. \<Page\> needs a connection to load and save changes." No permission = what the user can still do
+ "Ask your Plant Admin/IT for access." A refusal names the thing that blocks it.
